## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это ссылка на коммит (указатель), а не копия файлов. Создание, переключение и удаление ветки выполняются мгновенно и не зависят от объёма репозитория.

В SVN ветка — это копия директории в центральном репозитории. Даже с учётом механизма «дешёвых копий» операция выполняется на сервере, требует сетевого взаимодействия и создаёт дополнительную нагрузку.

Вывод: в Git ветвление — операция над указателями (O(1)); в SVN — операция над структурой репозитория (дорого по времени и ресурсам).

---

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нельзя, так как SVN — централизованная система: история хранится только на сервере. Локально доступны лишь рабочая копия и ограниченные операции (`svn status`, `svn diff`). Фиксация изменений (commit) требует соединения с сервером.

В Git коммит выполняется локально, поскольку каждый разработчик обладает полной копией репозитория. Сеть необходима только для синхронизации (`push` / `pull`).

## 3. В каких сценариях SVN может быть предпочтительнее Git?

1. Legacy-проекты в госсекторе и банках, где миграция на Git экономически нецелесообразна.
2. Работа с крупными бинарными файлами (графика, CAD, видео): SVN поддерживает частичный чекаут, в Git для этого требуется Git LFS.
3. Строгий централизованный контроль доступа по директориям.
4. Команды с низким порогом освоения распределённых систем.
5. Простые линейные workflow в малых командах.
